## 💻 Hands-On Exercises (Progressive Complexity)

### Exercise 2.1: Simple Agent (No Memory)
- Build research agent with tool use
- Understand basic loop structure
- Experience stop_reason handling
- **Time:** 30 minutes
- **Concepts:** Tool use, basic loop, error handling

### Exercise 2.2: Persistent Memory Agent
- Add database persistence
- Simulate crash/recovery
- Understand memory reconstruction
- **Time:** 45 minutes
- **Concepts:** Database schema, transaction safety, recovery patterns

### Exercise 2.3: Loop Detection
- Detect infinite loops
- Track tool call history
- Implement breaking logic
- **Time:** 20 minutes
- **Concepts:** Loop detection, state tracking, safety limits

### Exercise 2.4: Memory Summarization
- Implement token-aware summarization
- Prevent context window overflow
- Compare strategies (buffer vs. summary vs. semantic)
- **Time:** 40 minutes
- **Concepts:** Token budgeting, summarization, memory tiers

### Exercise 2.5: Robust Error Handling
- Implement retry logic with backoff
- Handle different error types
- Graceful degradation
- **Time:** 30 minutes
- **Concepts:** Transient vs. fatal errors, circuit breakers

### Exercise 2.6: Multi-Framework Comparison
- Build same agent in Claude SDK, LangChain, LangGraph
- Compare code complexity
- Understand trade-offs
- **Time:** 90 minutes
- **Concepts:** Framework patterns, abstractions, when to use each

## 🎓 Decision Framework: Which to Learn?

### You Should Learn Claude SDK If:
- ✅ You want maximum control
- ✅ You're building safety-critical systems
- ✅ You need deep debugging/observability
- ✅ You're an AI architect (not just user)
- ❌ You want quick prototyping (try LangChain first)

### You Should Learn LangChain If:
- ✅ You want fast prototyping
- ✅ You're new to agents
- ✅ You need memory management out-of-box
- ✅ You work with multiple LLMs
- ❌ You need complex state machines (use LangGraph)

### You Should Learn LangGraph If:
- ✅ You have complex workflows
- ✅ You need conditional logic & branching
- ✅ You want to visualize agent behavior
- ✅ You're building multi-step pipelines
- ❌ You're building your first agent (start with Claude SDK)

### You Should Learn AutoGen If:
- ✅ You're building multi-agent systems
- ✅ You want agents debating/collaborating
- ✅ You're teaching AI concepts
- ❌ You need production reliability
- ❌ You need transparent cost control

### You Should Learn Crew AI If:
- ✅ You want role-based agent teams
- ✅ You want super fast prototyping
- ✅ You like structured approaches
- ❌ You need fine-grained control
- ❌ You need to debug agent decisions

## 📝 Sample Assessment Questions (Scenario-Based)

### Scenario 1: Memory Recovery
**Context:** "Your agent runs 24/7. Every 1000 iterations, it crashes due to OOM. When it restarts, it should pick up where it left off."

**Question:** Design memory persistence strategy. Write pseudocode for save/load.

**Deep Probes:**
1. What's stored in database? Only messages or also state?
2. What if message is partially written when crash happens?
3. How do you prevent duplicate message processing on recovery?
4. Scale: What if agent has 1 million messages? How do you load it quickly?

**Scoring:**
- Level 1: "Save messages to database"
- Level 2: Includes schema, basic recovery logic
- Level 3: Handles race conditions, partial writes, scaling
- Level 4: Discusses transaction isolation, idempotence, optimization

---

### Scenario 2: Cost Control
**Context:** "Agent can call expensive tools (e.g., web search costs $0.01 per call). You bill customers $0.10 per query. Agent uses 20 tools per query on average = $0.20 cost, but revenue only $0.10. You're losing money."

**Question:** Design cost control system. How do you prevent agent from overspending?

**Deep Probes:**
1. Should agent know tool costs? How?
2. When agent exceeds budget, what happens? Stop? Switch to cheaper tool?
3. How do you handle agents that almost hit budget?
4. How do you communicate budget to the agent?

**Scoring:**
- Level 1: "Set a spending limit"
- Level 2: Includes per-tool costs, budget tracking
- Level 3: Discusses agent awareness, tool alternatives, alerts
- Level 4: Includes cost prediction, tool selection algorithms, SLA guarantees

---

### Scenario 3: Infinite Loop Detection
**Context:** "Agent gets stuck calling search tool repeatedly. Each search returns slightly different results, but agent keeps calling it. After 15 minutes and 30 searches, you've wasted compute. User is angry."

**Question:** How would you detect this? Fix it? Prevent it?

**Deep Probes:**
1. How do you distinguish "legitimate search" from "stuck loop"?
2. Semibold: Tool A called 3x in a row. Is that always bad? (No: legitimate if results changing)
3. How do you track tool call patterns?
4. What's your circuit breaker strategy?

**Scoring:**
- Level 1: "Track tool history, detect repetition"
- Level 2: Includes detection code, simple threshold
- Level 3: Discusses patterns, distinguishes productive from unproductive loops
- Level 4: Includes cost-aware decisions, graceful degradation, user notification

---

### Scenario 4: Framework Selection
**Context:** "You need to build an agent that solves complex math problems. It must:
- Show its work (step-by-step reasoning)
- Be correctable by humans
- Allow agents to collaborate (one agent solves sub-problem, another combines results)
- Run in production (1000 concurrent users)"

**Question:** Which framework? Why? What are trade-offs?

**Expected Answer Levels:**
- **Level 1:** "LangChain or Claude SDK"
- **Level 2:** "LangGraph for state machine + multi-step + visualization"
- **Level 3:** "LangGraph for complex workflows, but might need Claude SDK layer for cost control and observability"
- **Level 4:** "LangGraph for main agent, Claude SDK for sub-problems, custom orchestration layer for cost/scaling"
