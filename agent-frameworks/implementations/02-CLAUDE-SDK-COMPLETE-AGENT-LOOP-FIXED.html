🎯 Section 1: The Application We're Building

Concrete Goal: Build a Research Agent

What it does: Finds Python learning resources and summarizes them

User input: "Find 3 Python learning resources and summarize what they do"

Agent should:

  1. Search for "Python learning resources"
  2. Get back: "Python.org, Real Python, Codecademy"
  3. Search each one individually to learn details
  4. Collect all information
  5. Summarize findings in a final answer

Why this needs a loop: Can't do everything in one API call. Each tool result feeds back to the model, which then decides what to do next. Requires multiple iterations.

↓

↓
Execute 3 More Searches for Details
↓
Model Reads All Results → Summarizes
↓
Final Answer to User ✓

Notice: This requires multiple iterations. The loop pattern makes this possible.

A programmer thinks: "I'll just call the API, use the response, and loop if needed."

Broken Code: The Full Picture

def research_agent_broken(): client = Anthropic() messages = [{"role": "user", "content": "Find Python resources"}] # First API call response = client.messages.create( model="claude-3-5-sonnet-20241022", max_tokens=1024, tools=TOOLS, messages=messages ) # BUG #1: Unsafe indexing - assumes response.content[1] exists tool_call = response.content[1] # ❌ CRASHES! # BUG #2: Even if we skip that, formatting is broken tool_result = "Found: Python.org, Real Python, Codecademy" messages.append(tool_result) # ❌ WRONG FORMAT (no tool_use_id) # BUG #3: No check on stop_reason # ❌ Don't know if model is done or wants to continue # BUG #4: No safety limit # ❌ Could loop infinitely if model keeps calling tools # BUG #5: Messages created in wrong scope # ❌ If we had a loop, messages would reset each iteration

💥 Section 3: The Errors (What Actually Happens)

Error #1: IndexError - response.content[1] Doesn't Exist

1

The Code: tool_call = response.content[1]

What Happens: The API returns a response with only 1 block (just text), not 2. Trying to access index [1] when it doesn't exist = CRASH.

Error Message: IndexError: list index out of range

Why This Happens: The response structure depends on what the model decides to return. Sometimes it's [text], sometimes [text, tool_use], sometimes [tool_use]. You can't assume.

Error #2: Lost Message History

2

The Code: Creating messages list inside the function, but not preserving it across iterations

What Happens: First iteration works. Second iteration? The agent has no memory of the first search. It forgets context.

Why This Matters: The agent can't reason about previous results. It starts fresh each time like it has amnesia.

Error #3: Broken Tool Result Format

3

The Code: messages.append(tool_result)

What Happens: You send back just the raw result text. The model doesn't know which tool call this result belongs to.

Why This Fails: If you had 2 tool calls, which result goes with which? The model can't tell. It's ambiguous and breaks reasoning.

Error #4: No Exit Condition

4

The Code: No check on response.stop_reason

What Happens: The code doesn't know if the model wants to keep going or is done. It might exit too early or... keep looping.

Why This Matters: You lose control over when the agent finishes.

Error #5: Runaway Loop (No Safety Limit)

5

The Code: No max_iterations limit

What Happens: If the model gets confused and keeps calling tools, the loop never stops. You keep spending money on API calls.

Why This Matters: Unpredictable costs, wasted compute, potential infinite loops.

✅ Section 4: The Fixed Version (Production Grade)

Now that you understand WHY the naive version breaks, here's the correct way to write it.

Core Fixes Applied

❌ Broken Approach

  • Assume response structure
  • Messages created wrong scope
  • Raw result text (no linking)
  • No stop_reason check
  • No iteration limit

✅ Fixed Approach

  • Loop + type check (safe)
  • Messages persist outside loop
  • Structured results with tool_use_id
  • Check stop_reason always
  • max_iterations safety limit

Fixed Code: Detailed Walkthrough

def research_agent_FIXED(): client = Anthropic() # ✓ FIX #1: Create messages ONCE, outside loop messages = [] messages.append({"role": "user", "content": "Find Python resources"}) # ✓ FIX #5: Add safety limit max_iterations = 5 iteration = 0 while iteration < max_iterations: iteration += 1 # Call the API response = client.messages.create( model="claude-3-5-sonnet-20241022", max_tokens=1024, tools=TOOLS, messages=messages # ✓ Uses persisted history ) # ✓ FIX #2: Safe iteration (loop + type check) has_tool_use = False for block in response.content: if block.type == "text": print(block.text) elif block.type == "tool_use": has_tool_use = True tool_name = block.name tool_input = block.input tool_use_id = block.id # ✓ Save this # Execute tool tool_result = execute_web_search(tool_input["query"]) # ✓ FIX #3: Add result WITH tool_use_id messages.append({ "role": "user", "content": [{ "type": "tool_result", "tool_use_id": tool_use_id, # ✓ CRITICAL: Link result to call "content": tool_result }] }) # ✓ FIX #4: Check stop_reason to know when to exit if response.stop_reason == "end_turn": print("✅ Agent finished") break if not has_tool_use: print("✅ No tools used, we're done") break if iteration >= max_iterations: print(f"⚠️ Stopped at iteration limit: {max_iterations}")

Key Differences:

  • Line 1-2: Messages created OUTSIDE loop, persists
  • Line 14: Loop through blocks, check type (no assumptions)
  • Line 23-31: Tool result includes tool_use_id (structured format)
  • Line 33-39: Check stop_reason (explicit exit condition)
  • Line 41: max_iterations safety limit

🔄 Section 5: The 4-Phase Loop Explained

The fixed code follows a predictable 4-phase pattern. Every agent loop is this:

Phase ① GATHER CONTEXT

Add the user's question to the messages. This is the first thing the model reads.

messages.append({"role": "user", "content": "Find Python resources"})

Phase ② REASON & DECIDE

Call the Claude API. The model reads the messages and decides what to do.

response = client.messages.create( model="claude-3-5-sonnet-20241022", tools=TOOLS, messages=messages )

Phase ③ TAKE ACTION

Execute the tools the model selected. Capture the results.

for block in response.content: if block.type == "tool_use": result = execute_tool(block.name, block.input) # Now we have the result

Phase ④ OBSERVE & REFLECT

Add the tool results back to messages. Check if we should exit or loop again.

messages.append({ "role": "user", "content": [{ "type": "tool_result", "tool_use_id": block.id, "content": result }] }) # Check exit condition if response.stop_reason == "end_turn": break

This cycle repeats: GATHER → REASON → ACT → OBSERVE → (back to GATHER)

💡 Section 6: Key Insights

Insight 1: Messages Are State

The messages list IS the agent's memory. Every message you add stays in context. If you lose the list, the agent loses its mind.

Insight 2: Block Types Matter

Never assume response structure. Always loop and check block.type. This is the difference between fragile and robust code.

Insight 3: tool_use_id Is The Link

When you send back a tool result, include the tool_use_id. This is what links the result to the original tool call. Without it, the model is confused.

Insight 4: stop_reason Is Your Guide

stop_reason tells you why the model stopped. "end_turn" = done. "tool_use" = keep going. Always check it.

Insight 5: Limits Protect You

Always set max_iterations. This prevents runaway loops and unexpected costs. It's a safety guardrail.
