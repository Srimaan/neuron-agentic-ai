Prompt Engineering 101

Chapter 1 | Week 1: Agent Framework Foundations

What is Prompt Engineering?

Prompt engineering is the art and science of crafting inputs to LLMs that consistently produce desired outputs. It bridges the gap between what you want the model to do and what the model actually understands.

Think of it like:

  • Bad analogy: "Please write good code" - too vague
  • Good analogy: "Write Python code to validate email format, include type hints, and add unit tests" - specific, actionable

Core Principles

1. Clarity & Specificity

The more specific your prompt, the better the output. Vague prompts lead to vague results.

❌ Unclear Prompt
"Write a function for data processing"
✅ Clear Prompt
"Write a Python function that takes a CSV file path, reads customer data, filters records where age > 21, and returns a sorted list by purchase amount (descending). Include error handling for missing files."

2. Context is Everything

Provide background information about the domain, problem constraints, and expected outcomes.

✅ Prompt with Context
"You are a loan evaluation system for a fintech company. Customer data includes: credit_score (600-800), annual_income ($20k-$500k), employment_years (0-50). Rules: - Minimum credit: 600 - Maximum debt-to-income: 43% - Minimum employment: 2 years Evaluate this customer and return APPROVE or DENY with reasoning."

3. Structure & Format

Tell the model exactly what format you want for the output.

✅ Structured Output Request
"Return your response as JSON: { \"decision\": \"APPROVE\" or \"DENY\", \"confidence\": 0.0-1.0, \"reasoning\": \"...\", \"risks\": [\"...\"] }"

4. Role Definition

Tell the model what role to play or expertise to use.

Role Prompt Start
Expert Developer "You are a senior software architect..."
Domain Specialist "You are a credit risk analyst..."
Critic "Review this code and identify flaws..."
Teacher "Explain this concept to a beginner..."

Advanced Patterns

Chain-of-Thought (CoT)

Ask the model to show its reasoning step-by-step before answering.

"Let me think through this step-by-step: 1. First, I'll analyze... 2. Then I'll evaluate... 3. Finally, I'll conclude..."

Few-Shot Learning

Provide examples of the pattern you want followed.

Few-Shot Prompt
Examples: Input: "Customer credit 580" Output: {"eligible": false, "reason": "Below minimum"} Input: "Customer credit 720" Output: {"eligible": true, "reason": "Meets all criteria"} Now evaluate: Input: "Customer credit 650" Output:

System vs User Messages

Use system messages for instructions and user messages for requests.

Type Purpose Example
System Setup & constraints "You are a helpful assistant..."
User Specific request "Please evaluate this customer..."
Always structure prompts with clear sections: Role → Context → Task → Format

Prompt Template

# ROLE You are a [specific role/expertise] # CONTEXT [Background information about the domain] [Relevant constraints or rules] # TASK [Specific action to perform] [Any decision criteria] # OUTPUT FORMAT [Expected format - JSON, markdown, etc.] # EXAMPLE [One or two examples of good outputs] # CONSTRAINTS - [Constraint 1] - [Constraint 2]

Common Mistakes to Avoid

  • ❌ Being too vague - "Do something smart"
  • ❌ Not specifying output format - expect confusion
  • ❌ Forgetting context - model doesn't know your domain
  • ❌ Mixed instructions - keep role, task, and format separate
  • ❌ No examples - show don't just tell
  • ❌ Contradictory constraints - be consistent

Testing Your Prompts

Good prompts produce consistent results. Test by:

  1. Running same prompt 3-5 times with different inputs
  2. Checking if outputs match expected format
  3. Verifying reasoning is sound
  4. Testing edge cases (empty data, extreme values)
  5. Comparing with baseline (simpler prompt)
Spend 80% time on prompt design, 20% on code. A great prompt > average code with bad prompt.

Key Takeaways

  • Specificity beats brevity - be detailed
  • Context is crucial - explain the domain
  • Format matters - tell model exactly how to respond
  • Role definition helps - give expertise level
  • Examples work - show patterns, don't just describe
  • Test everything - consistency is key
