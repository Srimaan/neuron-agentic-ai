What is Context?

Context is all the information Claude uses to make decisions in a conversation.

Examples of context:

  • User's message (explicit request)
  • Customer history and profile
  • Business policies and rules
  • Market data and benchmarks
  • Company documents and references
  • Previous conversation turns (memory)
Important: Context ≠ Memory
• Context: Information in the current conversation
• Memory: Information persisted across conversations

Claude's Context Window

Claude 3.5 Sonnet has a 200,000 token limit per conversation.

Think of it like a library with limited space:

  • Input tokens: Everything Claude reads (context + your message)
  • Output tokens: Everything Claude writes in response
  • Total budget: 200,000 tokens per conversation

What Takes Tokens?

Content Type Tokens Example
Short sentence 20 "Hello world"
Paragraph 100 ~300 words
Page of text 400 ~1000 words
Code file 100-500 Varies by size
Full document 1000+ Average 5-10 pages

Token Counting

Always count tokens before sending. It affects cost and performance.

import anthropic

client = anthropic.Anthropic()

response = client.messages.count_tokens(
    model="claude-3-5-sonnet-20241022",
    messages=[{
        "role": "user",
        "content": your_context + "\n\n" + your_message
    }]
)

print(f"Input tokens: {response.input_tokens}")
print(f"Cache tokens: {response.cache_creation_input_tokens}")
💡 Tip: Always use count_tokens before sending large context. Costs: ~$3 per 1M input tokens.

4 Core Context Strategies

Strategy 1: Inline Context

Put context directly in the message.

✅ Pros

  • Simple and direct
  • Transparent
  • No dependencies

❌ Cons

  • Inefficient for large context
  • Repeated in each call
  • Can hit token limit fast

Strategy 2: System Message Context

Put persistent context in system prompt (~2K tokens max).

✅ Pros

  • Persistent
  • Efficient
  • Clear boundaries

❌ Cons

  • Limited size
  • Static (not dynamic)

Strategy 3: Database Retrieval

Fetch context dynamically from database.

✅ Pros

  • Dynamic and fresh
  • Scalable
  • Efficient

❌ Cons

  • Database latency
  • Complexity

Strategy 4: Chunking for Large Documents

Split large documents and process in pieces.

✅ Pros

  • Handles 50K+ tokens
  • Manageable chunks

❌ Cons

  • May lose context
  • Complex logic

Token Optimization

⚠️ Problem: Large context = High cost + Slow response
Context Size Input Tokens Cost (Sonnet) Speed
1 KB 250 $0.00075 Fast
10 KB 2,500 $0.0075 Medium
100 KB 25,000 $0.075 Slow
200 KB 50,000 $0.15 Very Slow

5 Compression Techniques

  1. Summarization: Replace documents with summaries (50K → 500 tokens)
  2. Filtering: Keep only high-relevance information
  3. Chunking: Process documents in pieces
  4. Caching: Save frequently used context
  5. Concise language: Use terse formatting

Long Context Applications

Use Case 1: Document Analysis

Process and analyze 50K+ token documents:

  • Split into chunks (10K tokens each)
  • Summarize each chunk
  • Combine summaries for final analysis

Use Case 2: Extended Conversations

Handle 100+ turn conversations:

  • Keep recent turns in full context
  • Summarize old turns when approaching limit
  • Monitor token growth each turn

Best Practices

✅ DO:

  • Count tokens before sending
  • Summarize large documents
  • Cache frequently accessed context
  • Prioritize important information
  • Use database retrieval for dynamic data
  • Monitor context growth
  • Compress old conversation history

❌ DON'T:

  • Send same large context repeatedly
  • Include irrelevant information
  • Forget to count tokens
  • Hardcode large context strings
  • Ignore database performance
  • Keep unlimited conversation history

🎓 Key Takeaways

  1. Context ≠ Memory: Current conversation vs persistent data
  2. 200K tokens: Claude's context window per conversation
  3. Token counting: Critical for cost and performance
  4. Retrieval: Pull context dynamically from databases
  5. Compression: Summarize to save tokens
  6. Monitoring: Track token usage to avoid surprises
  7. Trade-offs: Balance context size vs quality
