📚 Section 1: What We Already Learned

✅ The 4-Phase Agent Loop (Review)

Phase ①: Gather Context
Collect user intent, conversation history, environment state, available tools

Phase ②: Reason & Decide
LLM analyzes: What's the goal? What tools needed? In what order?

Phase ③: Take Action
Execute selected tools, capture results, handle errors

Phase ④: Observe & Reflect
Did action succeed? Is goal achieved? Should I continue loop or exit?

✅ Key Concepts We Know

✓ stop_reason tells us if agent wants to use tools or is done

✓ tool_use = agent wants to call a tool (continue loop)

✓ end_turn = agent is done (exit loop)

✓ Tool errors should return structured results, not crash

✓ Messages accumulate in conversation history

🆕 Section 2: What We're Learning Now

🔴 Problem with Previous Code

The code example you saw had critical issues:

tool_call = response.content[1] # ❌ Wrong! Assumes tool_use is at index 1

If response.content has text at index 0 and tool_use at index 1, this works. But if there's no text? Crashes!

The messages list wasn't being used. Tool results weren't passed correctly to LLM.

🟢 What We're Fixing Today

✓ Properly iterate through response.content blocks (don't assume index)

✓ Correctly format tool results for the LLM to understand

✓ Maintain message history across all loop iterations

✓ Handle no-tool-call case (when agent just responds with text)

✓ Exit gracefully when agent says it's done

🎯 Key Learning: response.content Structure

response.content is a LIST of blocks, like:

[ TextBlock(text="I'll search for..."), # Block 0: Agent's reasoning ToolUseBlock(id="...", name="search"), # Block 1: Agent wants to call tool ]

Never assume index! Loop through blocks and check their type.

📖 Section 5: Understanding Each Phase in Detail

PHASE ①: GATHER CONTEXT

What happens: Add user's query to messages list

messages.append({"role": "user", "content": user_query})

Why: The LLM needs to see conversation history to understand context

Example: If user previously asked about Python, then asks "how to optimize?", the LLM needs to know they mean Python optimization, not general optimization

PHASE ②: REASON & DECIDE

What happens: Call Claude API with messages and tools

response = client.messages.create(model="...", tools=TOOLS, messages=messages)

Why: The LLM reads everything (context + tools) and decides next action

Claude returns: Text (reasoning) + decision (use tool? or finish?)

PHASE ③: TAKE ACTION

What happens: Execute the tools agent requested

Check: if response.stop_reason == "tool_use" then we have tools to execute

Loop through ALL blocks in response.content (don't assume index!)

For each tool_use block: execute it and collect results

PHASE ④: OBSERVE & REFLECT

What happens: Add tool results back to messages so LLM can see them

messages.append({"role": "user", "content": tool_results})

Check: if response.stop_reason == "end_turn" then agent is done (exit loop)

Otherwise: Loop back to Phase ① with the new information

⚠️ Section 6: Wrong vs Right Way

❌ WRONG (What NOT to do)

tool_call = response.content[1] # Crashes if index 1 doesn't exist! messages.append(tool_result) # Messages never added, history lost result = execute_tool(tool_call.name) # What if tool fails? No error handling

✅ RIGHT (What to do)

for block in response.content: if block.type == "tool_use": # Safe! Checks type first messages.append({"role": "assistant", ...}) # Keep full history result = execute_tool(...) # Tool returns structured error if needed

⚠️ Most Common Mistake

Assuming index of tool_use block

Wrong: tool_call = response.content[1] # ❌

Right: for block in response.content: if block.type == "tool_use": # ✅

Why? The LLM might return: [TextBlock, ToolUseBlock] OR just [ToolUseBlock] OR [TextBlock, TextBlock]

✅ Best Practice

Always maintain messages list

Step 1: Add user message (Phase ①)

Step 2: Get response (Phase ②)

Step 3: Add assistant response to messages

Step 4: Execute tools (Phase ③)

Step 5: Add tool results to messages (Phase ④)

Step 6: Loop back with updated messages (next iteration continues conversation)

💡 Section 8: Key Insights & Lessons

Insight 1: Messages Are Your Memory

The messages list IS your agent's memory. If you don't add to it, the LLM loses context.

Iteration 1: LLM sees [user_query]

Iteration 2: LLM sees [user_query, assistant_response, tool_result]

This is how the agent "learns" from previous tool results!

Insight 2: Never Assume Index

Claude's response can have multiple blocks in ANY order:

✓ [Text, ToolUse, Text]

✓ [ToolUse, ToolUse, Text]

✓ [Text] (no tools)

✓ [ToolUse] (no text)

Always loop and check type: if block.type == "tool_use":

Insight 3: Loop Control

Two ways to exit the loop:

Option A: stop_reason == "end_turn" (LLM says done)

Option B: iteration >= max_iterations (safety limit)

Always have max_iterations as safety catch! Prevents infinite loops.

Insight 4: Tool Results Format

Tool results MUST be formatted as:

{ "type": "tool_result", "tool_use_id": "...", # Must match the request ID! "content": "result text" }

If you forget tool_use_id, the LLM won't know which tool this result belongs to!
