Write a Loan Evaluation Prompt

Easy ⏱️ 30 min ⭐ Foundations

Challenge

You work at a bank. Write a prompt that Claude will follow EVERY TIME to produce the same output format.

Requirements

  • Clear role definition
  • Specific evaluation criteria
  • Scoring system
  • Decision thresholds
  • JSON output format
  • At least one example
Test Case:

Jane Smith, Credit: 680, Income: $75,000, Debt: $1,200/month, Loan: $40,000, Employed 2 years

Your prompt should produce consistent JSON with decision, reason, score, and factors.

ROLE: You are a loan evaluation system. OUTPUT FORMAT (JSON ONLY): { "decision": "approved" | "denied" | "review", "reason": "brief justification", "score": 0-100, "debt_to_income": number, "factors": ["list"] } SCORING: - Credit 750+: 80 pts (excellent) - Credit 700-749: 60 pts (good) - Credit 650-699: 40 pts (fair) - DTI < 0.25: 80 pts (excellent) - DTI 0.25-0.35: 60 pts (good) - DTI 0.36-0.45: 40 pts (fair) - Employed > 2 years: 20 pts - Employed < 2 years: 10 pts THRESHOLDS: - 200+: Approved - 150-199: Approved - 100-149: Review - < 100: Denied

Key Insight

  • Explicit is better than implicit
  • Numbers are more precise than descriptions
  • Format specification ensures consistent output
  • Examples show Claude what good looks like

Identify Problems in Broken Prompts

Easy ⏱️ 20 min ⭐ Debugging

Challenge

For each prompt, identify: (1) What's wrong, (2) How it fails, (3) How to fix it

Prompt A: Too Vague

"Evaluate this loan application and tell me if it's good or bad."

Problems:

  • No clear decision format ("good or bad" is ambiguous)
  • No criteria specified
  • No scoring system
  • No JSON format

Prompt B: Ambiguous Rules

"You are a loan officer. Approve loans if they seem reasonable."

Problems:

  • "Seem reasonable" is undefined
  • No numerical thresholds
  • Claude will guess what "reasonable" means
  • Inconsistent decisions

Prompt C: Missing Examples

"Evaluate this loan. Provide your analysis."

Problems:

  • No examples of approved/denied applications
  • Claude doesn't know what "good" looks like
  • Decisions will be inconsistent

Key Insight

  • Vague prompts → vague outputs
  • Examples teach Claude what you want
  • Specificity = consistency

Test Prompt Consistency

Medium ⏱️ 40 min ⭐ Validation

Challenge

Write code that evaluates 3 different applications with your prompt and checks if decisions are consistent.

Key Testing Pattern: Same prompt → 3 different apps → Compare decisions

import json from anthropic import Anthropic client = Anthropic() SYSTEM_PROMPT = """Your prompt here""" def test_loan(app, test_num): """Evaluate and show result""" message = client.messages.create( model="claude-3-5-sonnet-20241022", max_tokens=500, system=SYSTEM_PROMPT, messages=[{"role": "user", "content": app}] ) result = json.loads(message.content[0].text) print(f"Test {test_num}: {result['decision']}") return result # Run 3 test cases test_cases = [ ("Good: 750 credit, $100k income", "approved"), ("Borderline: 680 credit, $60k income", "review"), ("Risky: 580 credit, $40k income", "denied") ] for app, expected in test_cases: result = test_loan(app, 1) if result['decision'] == expected: print("✅ Correct!") else: print("❌ Unexpected")

Key Insight

  • Test with multiple scenarios
  • Verify consistent decisions
  • Check JSON format is always valid
  • Edge cases reveal prompt weaknesses

Challenge

LangChain Implementation

from langchain.prompts import ChatPromptTemplate prompt = ChatPromptTemplate.from_messages([ ("system", "Your system prompt here"), ("human", "{application}") ]) # Same prompt, different interface

LangGraph Implementation

from langgraph.graph import StateGraph graph = StateGraph(dict) def evaluate_node(state): """Use same prompt in node""" response = client.invoke({ "system": "Your system prompt here", "user": state["application"] }) return response

Key Insight

  • Prompts are framework-agnostic
  • Only the delivery method changes
  • Same logic, different wrapper

Improve Prompt Based on Failures

Hard ⏱️ 60 min ⭐ Mastery

Challenge

Imagine your prompt is approving risky loans and denying good ones. Write an improved version that handles edge cases better.

Strategy: Add explicit rules, better edge case handling, clearer thresholds.

CRITICAL RULES: 1. ALWAYS output valid JSON 2. ALWAYS calculate exact numbers 3. NEVER approve if credit < 650 4. NEVER approve if employment unverified 5. ALWAYS escalate borderline cases EXCEPTION HANDLING: IF credit < 600 AND employment unverified: → MUST ESCALATE IF debt-to-income > 0.5 AND credit < 700: → MUST ESCALATE IF assets < $5k AND loan-to-income > 5: → MUST REVIEW

Key Insight

  • NEVER and MUST are stronger than "should"
  • Edge cases need explicit handling
  • Escalate when unsure
  • Defensive programming helps
